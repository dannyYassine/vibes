§ 00

Layering rules — read before writing code

10 rules

The codebase follows strict clean-architecture layering. Dependencies flow one direction only:

delivery mechanisms (views, jobs, commands)
        ↓ build DTO, call one usecase
application (use cases)
        ↓ call
services (core/domain)
        ↓ call
repositories, factories, handlers
        ↓ hydrate / create
models (domain entities)

Hard rules — violate these and the build is wrong:

  1. One use case per request. A view or job builds exactly one DTO and calls exactly one usecase.execute(dto). Never two.
  2. Views never touch repositories. Views call use cases only.
  3. Use cases never import Django. They take ports (ABCs) as constructor args. Django lives only in infrastructure/.
  4. Repositories return domain entities, never ORM models. Hydrate via Entity.fromDatabase(row).
  5. Handlers are pure functions, constructed with plain vars, never DI-registered. For v1, ExactMatcher / TitleNormalizer are handlers called by CategorizationService.
  6. DTOs are data only. No methods. Built by the delivery mechanism, passed to usecase.execute(dto).
  7. Presenters never call services/repositories. They take use-case output, build a ViewModel, pick a Component.
  8. Templates read vm.* only. No computation, no formatting in templates.
  9. AUTO_APPROVE_THRESHOLD is a class attribute on AutoCategorizeUseCase, not a Django setting.
  10. Credentials never committed, never logged. .env only, gitignored.

docker-compose is set up NOW so it is available for every subsequent step. Three services: db (Postgres 16-alpine), web (Django runserver), qcluster (Django-Q2 worker). No broker container.

One shared Dockerfile for web + qcluster (two services, two commands) — reduces drift. Base python:3.12-slim, installs uv, syncs deps, runs playwright install --with-deps chromium.

Exceptions

Flagged in red pencil — resolve before the matcher ships

  • Normalization samples missing. Pull 30–50 real RBC transaction descriptions into samples/rbc_descriptions.txt. RBC embeds store numbers / ref codes / dates in descriptions (TIM HORTONS #4521 vs #0192) — the normalization rule must be locked against real samples. Until then, TitleNormalizer returns identity.
  • CSV parser schema assumed. EXPECTED_HEADERS and date format (MM/DD/YYYY) are assumptions — confirm against a real RBC export. Update csv_parser.py + its test + .okf/references/csv-parser.md if different.
  • RBC selectors unverified. Selectors in selectors.py are placeholders — inspect real RBC online banking DOM via Playwright headed mode and patch. Scraper is designed so this is the only file to touch.

Footnotes — risk register

  1. 01RBC login UI breaks. Selectors in one file; Playwright downloads CSV not DOM-scrapes; alert on SyncFailed.
  2. 02RBC changes CSV format. csv_parser.py schema-validated; fail loudly, not silently.
  3. 03RBC blocks headless automation. Spoof user-agent, disable AutomationControlled. Fall back to manual CSV upload (out of v1 scope).
  4. 04ORM broker lost job on crash. Django-Q2 ORM broker persists to DB; retry=120 requeues. Acceptable for 2-person tool.
  5. 05Pi SD card corruption. USB SSD boot only; daily pg_dump + rclone.
  6. 06Spouse can't reach Pi when traveling. Tailscale on phones; Tailscale Funnel if public HTTPS needed.
  7. 07Credential leak. .env only, gitignored; django-environ; never logged.
  8. 08Exact match under-matches. times_confirmed counter + manual approve reinforces rules. Revisit fuzzy only if hit rate <60% after 3 months.
